# run-log

## このスキルがすること

ランニング記録のインプット（スクリーンショット画像 or 文字起こしテキスト）を受け取り、以下を一気通貫で行う。

1. データ抽出（サマリー + スプリット）
2. 対象の大会ディレクトリの特定
3. `results.csv` / `splits.csv` への追記
4. `plan.md` との照合
5. `evaluations.md` への評価コメント追記

各ファイルのカラム定義・データ規約はリポジトリ直下の `CLAUDE.md` に定義されている。矛盾があれば `CLAUDE.md` を正とする。

## Step 1: データを抽出する

画像が渡された場合は Read ツールでそのまま読み込んで内容を読み取る。テキストが渡された場合はそのテキストから同様の項目を読み取る。

読み取る値は2種類ある。

**サマリー（1走行につき1組）**

`date, start_time, end_time, distance_km, avg_pace_sec, best_pace_sec, running_time_sec, elapsed_time_sec, calories_kcal, avg_cadence_spm, elevation_gain_m, elevation_loss_m, avg_hr_bpm, max_hr_bpm`

**スプリット（km単位、画面にあれば取得。無ければスキップしてよい）**

`date, km, split_pace_sec, pace_diff_sec, elevation_change_m, hr_bpm`

抽出時の変換ルール:

- ペース・時間はすべて秒数の整数に変換する。表示形式の文字列（`6'23"` や `50:09`）はCSVに残さない。`分'秒"` 形式も `MM:SS` 形式も「分×60＋秒」で秒数化する
- 高低差は上り・下りをそれぞれ正の数値（メートル）として記録する（`+53m` → `elevation_gain_m=53`、`-55m` → `elevation_loss_m=55`）
- スプリットの `pace_diff_sec` は前kmとの差分。表示が `+0'14"` なら `+14`、`-0'06"` なら `-6` のように符号付き秒数にする
- 読み取れない・画面に存在しない項目は空欄のままにする。値を推測して埋めない

## Step 2: 対象の大会ディレクトリを特定する

`races/` 配下は `races/YYYY-MM-DD-大会名/` という命名になっている。以下の手順で書き込み先を決める。

1. `races/` 配下のディレクトリを列挙する
2. ディレクトリが1つもなければ、大会ディレクトリの作成はこのスキルの範囲外なので処理を止め、大会ディレクトリをまず作る必要があることをユーザーに伝える
3. 各ディレクトリ名の先頭10文字（`YYYY-MM-DD`）を開催日として解釈する
4. 今日以降の開催日を持つディレクトリのうち、最も開催日が近いものを書き込み先として自動選択する
5. 該当ディレクトリが1つしかない場合はそれを使う。判断に迷うケース（今日以降の開催日を持つディレクトリが複数あり優先度が読み取れない等）はユーザーに確認する

## Step 3: results.csv / splits.csv に追記する

選択した大会ディレクトリの `results.csv` にサマリー1行を追記する。スプリットデータが取得できていれば、同ディレクトリの `splits.csv` にも各kmを1行ずつ追記する。ヘッダー行はすでに存在するので、値の行だけを追加する。

## Step 4: plan.mdと照合する

同じ大会ディレクトリの `plan.md` を読み、抽出した `date` の曜日に対応する週次メニュー表の行を探す。

- 該当する曜日の行にメニューが記入されていれば、それを「予定」として実績（distance_km・avg_pace_sec等）と比較する
- 該当週や該当曜日の記入がまだない場合は、「計画未記入」として扱い、無理に達成判定をしない

## Step 5: evaluations.mdに追記する

同じ大会ディレクトリの `evaluations.md` に、`## YYYY-MM-DD（曜日）` の見出しで新しいエントリを追記する（既存エントリの上書きはしない。同じ日付が渡された場合はユーザーに上書きか追記かを確認する）。

エントリの構成はテンプレートに準拠し、以下4観点すべてに具体的な内容を書く。空欄のまま残さない。

- **計画照合**: 予定・実績・判定（達成/超過/未達など）
- **目標に対する進捗**: `plan.md` に書かれた目標タイムに対して、今回のペース・心拍がどう位置づけられるか
- **体調・回復度・怪我リスク**: 心拍の上昇傾向、ペースの乱れ、直近の記録との比較から気になる点があれば指摘する。特に問題がなければその旨を書く
- **次回メニューの提案**: 今回の内容と `plan.md` の次回予定を踏まえた具体的な提案

## 参照ファイル

- `CLAUDE.md`: プロジェクト全体の構成とデータ規約
- `templates/results.csv` / `templates/splits.csv`: カラム構成の正本（大会ディレクトリ内のファイルもこれと同じ構成）
- `templates/evaluations.md`: 評価エントリのテンプレート
